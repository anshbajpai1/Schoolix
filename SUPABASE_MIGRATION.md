# Schoolix Firebase to Supabase Migration

## Current Increment

This increment migrates the browser/client data layer away from Firebase SDK imports while preserving the existing UI and page-level business logic.

Modified runtime files:

- `firebase-compat.js`: Firebase-style compatibility facade backed by Supabase Auth and the `firestore_documents` PostgreSQL table.
- `firebase.js`: now exports Supabase-backed `auth` and `db`.
- `supabase-config.js`: central Supabase URL and anon key.
- `app.js`: CSP allows the Supabase JS browser SDK CDN.
- All root HTML/JS files that imported Firebase CDN modules now import `./firebase-compat.js`.
- `scripts/build-mobile.mjs`: copies `firebase-compat.js` and `supabase-config.js` into `www` and `hosting`.
- `hosting/*` and `www/*`: regenerated by the existing build script.

Database/migration files:

- `supabase/migrations/202607300001_schoolix_postgres_backend.sql`
- `scripts/migrate-firestore-to-supabase.mjs`
- `scripts/migrate-firebase-auth-to-supabase.mjs`

Package changes:

- Removed client `firebase` dependency.
- Added `@supabase/supabase-js` and `firebase-admin`.
- Added scripts:
  - `npm run migrate:firestore`
  - `npm run migrate:auth`

## Database Setup

Apply the SQL migration before loading migrated data:

```bash
supabase db push
```

The migration creates:

- `firestore_documents`: compatibility table preserving every Firestore document path and ID.
- Normalized core tables for schools, users, students, staff, fees, attendance, accounts, report cards, and notices.
- Indexes for school/collection lookups, JSONB search, fees, attendance, accounts, students, and roles.
- RLS helper functions and policies based on the original Firestore rules.

## Firestore Data Migration

Set these environment variables:

```bash
SUPABASE_URL=...
SUPABASE_SERVICE_ROLE_KEY=...
FIREBASE_SERVICE_ACCOUNT_PATH=path/to/firebase-service-account.json
```

Then run:

```bash
npm run migrate:firestore
```

For a no-write test:

```bash
DRY_RUN=true npm run migrate:firestore
```

This recursively migrates every Firestore collection/subcollection into `firestore_documents` while preserving document paths and IDs, then backfills normalized tables.

## Auth Migration Strategy

Firebase Auth passwords cannot be read through the Firebase Admin SDK, so automatic password preservation is not possible with the current local inputs.

Safe path:

1. Run the auth script in dry-run mode first:

   ```bash
   DRY_RUN=true npm run migrate:auth
   ```

2. Review `supabase-auth-migration-users.json`.
3. Run with `DRY_RUN=false` to create Supabase Auth users with temporary passwords.
4. Send reset links / temporary-password instructions using the existing email flow.

If you can export Firebase Auth password hashes from Google Cloud Identity Platform, migrate via Supabase's hash-import path instead to preserve existing passwords.
